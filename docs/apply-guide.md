# 申请与选择指南

[返回首页](../README.md)

先确定需要的资源，再按身份选择计划。模型API只能调用厂商支持的模型；Notebook适合短实验；独立GPU实例适合自定义环境；超算通常要通过机构和课题申请。

## 申请前准备

| 身份 | 常用材料 | 容易忽略的条件 |
|---|---|---|
| 学生 | 学校邮箱、有效在读证明、课程或项目说明 | 本科/硕士/博士资格不同，GitHub认证不能代替每家厂商认证 |
| 任课教师 | 院校邮箱、课程名称、人数、教学时段 | 教学实验额度常分配到课程沙箱，不能转为个人任意使用额度 |
| 研究人员 | 研究摘要、算力预算、机构信息、预计成果 | PI或教师申请资格、成果公开、致谢与报告要求 |
| 创业团队 | 企业注册信息、网站、商业邮箱、融资与投资机构信息 | 是否需合作方推荐、成立年限、融资阶段和历史领取记录 |
| 开源维护者 | 公开仓库、许可证、维护记录、项目用途 | 活跃度与实际影响，工具订阅和API赠金是否分别审批 |
| 非营利组织 | 注册证明、组织宗旨、项目与预算 | 官方慈善/公益资格，学校或个人不自动等同非营利组织 |
| 地方政策申报主体 | 属地信息、算力合同、发票、付款证明、使用记录 | 先用后补、指定服务商、申报年度和资金预算 |

## 描述算力需求

把计划写成可核对的工作负载，例如“单卡24GB显存，完成3组微调，每组预计8小时，需要80GB持久存储”，再列预计CPU、GPU、存储、网络与服务费用。不要只写“想要一张H100”。预算应说明估算依据，不能编造既有实验结果。

申请材料通常需要：项目要解决的问题、为何需要该资源、计划使用时段、预算分项、可交付成果和负责人。不同资助要求不同，以条目官方申请页为准。

## 四个检查

1. **身份与地区**：计划接收的是个人、学生、教师、机构还是已融资企业；中国大陆申请资格是否明确。
2. **额度与产品**：赠的是硬件时间、云抵扣还是API余额；GPU、存储、第三方模型等是否被排除。
3. **有效期与窗口**：申请截止日、领取截止日、开始使用日和额度到期日分别记录。
4. **到账后的费用**：绑定付款方式是否会自动扣费，额度耗尽是否停机，磁盘和快照是否继续收费。

## 领取之后

先在账户中确认实际到账金额、产品范围和到期日，再创建资源。为训练保存断点，保留审批通知和必要账单；遵守成果、致谢和使用范围要求。成本告警通常只是通知，不能默认它会自动停止资源。

未获批、等待回复或网页能打开都不等于获得算力。本仓库不代替用户申请，不代提交身份材料，不创建付费实例。
